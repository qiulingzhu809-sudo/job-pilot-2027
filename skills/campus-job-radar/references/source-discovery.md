# 多来源发现与核验

## 来源角色

发现源负责扩大公司覆盖，官方系统负责确认事实。发现源出现的岗位名称、截止时间和投递状态都不是最终结论。

| 来源 | 适合发现 | 线索置信度 |
| --- | --- | --- |
| 企业招聘官网、官方 ATS | 当前岗位与申请入口 | 最高 |
| 高校就业网、企业官方招聘号 | 定点校招、招聘简章与批次 | 高 |
| 牛客企业活动页、企业认证账号 | 活跃企业、岗位数量、招聘节奏 | 中高 |
| 牛客讨论区、实习僧、海投网 | 内推、中型公司和地域性机会 | 中 |
| JobHunter、GitHub 校招聚合项目 | 批量公司池和来源链接 | 中 |
| 普通转载、论坛汇总、搜索摘要 | 补充线索 | 低 |

## 轮换发现

每轮先从结构化来源取得一批公司，再从社区或高校来源补充另一批；记录来源，避免下一轮重复扫描同一批结果。搜索引擎只用于解析某家公司的官方入口或补齐缺失字段，不承担生成完整公司池的职责。

优先使用来源自身的目录、活动页、行业分类、日期列表或 API，而不是穷举“公司名 + 岗位”关键词。分页时按更新时间继续扫描，并设置本轮时间或数量上限；下一轮从上次游标继续。

## 官网收口

对每条线索执行：

1. 确认官网或企业官方 ATS 域名。
2. 在当前职位列表内筛选届别、岗位族和 Base。
3. 打开具体岗位详情，读取职责、要求、发布时间和申请控件。
4. 依据页面事实归类：
   - `已核验可投`：岗位详情存在，届别匹配，申请入口可用。
   - `岗位未确认`：官方项目存在，未找到对应具体岗位。
   - `疑似下线`：发现源有记录，官方当前列表搜索为零或详情失效。
   - `待登录核验`：登录后才能查看列表或详情。
5. 仅 `已核验可投` 进入结果 JSON，其余候选连同来源和失败原因写入本轮报告。

申请入口存在只代表页面当前允许进入申请流程，不推断 HC、远程面试、截止日期或处理速度。公众号独占且无法读取详情时保留为待核验候选。
